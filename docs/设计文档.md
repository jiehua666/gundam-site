## 一、项目定位

### 1.1 项目名称
**GUNDAM SITE**

### 1.2 核心定位
机体百科 + 创作者社区（两者结合）
- 不是单纯的机体信息站，也不是单纯的论坛
- 而是让用户在看机体、学机体、讨论机体的同时，能展示自己的作品、与其他爱好者互动

### 1.3 初期目标用户
**模型师**
- 喜欢做高达模型的玩家
- 会拍照、拍视频分享作品
- 有创作欲望，愿意展示成果

### 1.4 用户可做什么
- **浏览**：看机体信息、看他人作品
- **互动**：点赞、收藏、评论、关注、签到
- **创作**：上传自己的作品（图片、视频、3D模型）

### 1.5 内容形式
- **图片**：模型照片、插画作品
- **视频**：MMD动画、模型评测视频
- **3D模型**：.glb/.gltf格式，可在网页在线预览

## 二、付费模式

### 2.1 模式
订阅制（月/年订阅）

### 2.2 上线时间
先免费运营，后续再加付费
- 上线初期不收费，先积累用户
- 等用户量起来、运营稳定后再加付费功能

### 2.3 订阅档位

| 档位 | 价格 | 能做什么 |
|------|------|----------|
| **免费** | 0元 | 看简化版页面（不完整的详情）、基础互动（点赞、简单评论） |
| **基础档** | 9元/月 | 看完整页面、每月最多上传5张图、简单收藏功能 |
| **标准档** | 19元/月 | 无限上传图片+视频、每月最多3个3D模型、高级收藏+标签管理 |
| **高级档** | 29元/月 | 全部功能解锁、无限3D模型上传、专属高级标签、优先审核通道 |

### 2.4 免费用户限制
- 只能看到简化版页面（缺少详细参数，配图等）
- 想看完整的机体详情和作品详情，需要付费

### 2.5 补签卡绑定订阅

| 档位 | 补签卡数量 |
|------|-----------|
| 基础档（9元/月） | 0张/月 |
| 标准档（19元/月） | 1张/月 |
| 高级档（29元/月） | 3张/月 |

### 2.6 补签卡单独购买

| 项目 | 价格 |
|------|------|
| 单张购买 | 3元/张 |
| 套餐购买 | 5元/3张 |
| 每月限购 | 6张 |

### 2.7 补签卡规则
- **清零时间**：按用户注册日期每月重置（不是自然月），避免月中注册月底清零的不公平问题
- 例如：用户3月15日注册，则每月15日重置补签卡数量
- 每月清零，不累积
- 用于补签连续签到中断的天数

### 2.8 补签卡购买流程
与订阅购买独立，可单独购买：
1. 用户选择购买数量（单张/3张套餐）
2. 发起支付（微信/支付宝）
3. 支付成功后回调通知
4. 更新用户补签卡数量（checkin_cards字段+1或+3）
5. 补签卡立即可用

## 三、用户系统

### 3.1 登录方式
账号密码登录（后续可加第三方）

### 3.2 用户名规则
- 注册时填写的登录名，只能用英文和数字
- 用于登录系统，不可更改

### 3.3 昵称功能
- 用户可以设置一个中文或英文的显示名
- 显示在评论区、作品页等所有公开位置
- 可以随时修改

### 3.4 邮箱验证
计划中有，但先不做（后续实现，需要配置邮件服务器，防止垃圾注册）

### 3.5 角色系统（5个角色，与订阅独立）

| 角色 | 能做什么 | 怎么获得 |
|------|----------|----------|
| **创始人** | 最高权限，可以彻底删除数据，可以操作系统所有功能（包括财务、数据库恢复、授予管理员权限） | 项目创建者 |
| **普通用户** | 浏览、互动（点赞、收藏、评论、签到）、发作品（限制最多1篇） | 注册后默认 |
| **创作者** | 浏览、互动、发布作品（无数量限制）、有专属创作者主页 | 普通用户主动申请，管理员审批 |
| **审核员** | 审核用户提交的作品和机体信息 | 管理员授予 |
| **管理员** | 全站内容管理和用户管理（除禁区操作外） | 创始人授予 |

### 3.6 创作者升级条件
主动申请 + 管理员审批
- 普通用户觉得自己创作能力够了，可以提交申请
- 管理员审核通过后，升级为创作者
- 创作者可以获得专属主页，展示所有作品
- **审批时限**：7个工作日内处理，超时自动通过

### 3.7 普通用户限制
最多发1篇作品
- 普通用户只能发布1篇作品
- 想要发布更多，需要申请成为创作者

### 3.8 删除权限
- **创始人**：可以彻底删除数据（物理删除，从数据库里真正删掉）
- **其他角色**：只能软删除（标记 is_deleted=1，数据还在，可恢复）

### 3.9 关注/粉丝功能
需要
- 用户可以关注其他用户
- 被关注的用户会有粉丝数显示
- 可以看关注的人的动态

### 3.10 黑名单功能
需要
- 用户可以拉黑其他用户
- 拉黑后，双方互相看不到对方的内容
- 评论区不会显示被拉黑的人

### 3.11 私信功能
需要，规则特殊：单向提问式
- 用户之间只能发一条消息
- 对方必须回复后，才能继续对话
- 适合"提问-回答"场景，避免骚扰
- **对方不回复处理**：7天后自动解除对话锁定，可发起新对话
- **多次骚扰处理**：被拉黑后30天内不能向同一用户发私信

### 3.12 私信撤回
2分钟内可撤回

### 3.13 禁言/封禁功能

> **关联章节**：通知系统（十七）
> - 被禁言/封禁时触发系统通知（十七、17.1 审核通知类型扩展）

**禁言（临时）：**
- 影响：不能发评论、不能发作品、不能发私信
- 时长：临时（1天/3天/7天等）
- 显示原因：被禁言时显示原因（如"因违反社区规则被禁言"）
- **通知**：被禁言时发送系统通知，告知禁言原因和时长
- 触发方式：
  - 管理员手动执行
  - 自动触发：被举报3次且属实（禁言1天）、违规发言5次（禁言3天）、被投诉10次（禁言7天）

**封禁（永久/长期）：**
- 影响：不能登录，完全不能使用账号
- 时长：永久或长期
- **通知**：被封禁时发送系统通知，告知封禁原因
- 申诉：见3.14申诉功能
- 触发方式：
  - 管理员手动执行
  - 自动触发：被禁言3次后又违规（永久封禁）、严重违规（抄袭/盗用/攻击他人，直接封禁）、刷单/刷积分作弊（永久封禁）

### 3.14 申诉功能
- 用户被封禁后可申诉
- 申诉有效期：封禁后7天内
- 申诉处理时限：3个工作日内
- 申诉通过后自动解封

### 3.15 用户删除作品
可以（删除后软删除）

### 3.16 实名认证
计划中，后续实现

### 3.17 客服系统
暂时不做（人手不够，可直接看工单）

## 四、内容规则

### 4.1 创作关联
作品必须关联机体
- 用户上传作品时，必须选择一个关联的机体
- 例如：上传RX-78-2的模型照片，就关联到RX-78-2机体
- 便于内容聚合，用户想看某个机体的作品时能找到

### 4.2 机体来源
**两种来源：**
- 管理员预先录入（官方数据）：经典机体由管理员直接添加
- 用户贡献：用户可以申请添加新机体

### 4.3 机体审核
用户添加的机体需要审核
- 普通用户提交的机体不会直接显示
- 需要审核员或管理员审核通过后才公开

### 4.4 审核角色
管理员 + 审核员
- 都可以审核作品和机体
- 审核员主要负责内容审核
- 管理员可以做所有管理操作

### 4.5 内容审核
需要审核，先人工审，后续加AI
- 用户发布的作品不会直接公开
- 需要审核员/管理员审核通过
- **审核时限**：普通作品3个工作日内完成，超时自动通过

### 4.6 评论系统
需要评论嵌套（楼中楼）
- 评论可以回复，形成嵌套结构
- 方便对话，不是平铺的列表

### 4.7 用户删除评论
可以（删除后软删除）

### 4.8 作品编辑
可以编辑，但编辑后需重新审核

### 4.9 举报功能
需要
- 用户发现违规内容可以举报
- 举报后管理员/审核员处理
- **处理时限**：紧急举报（色情/政治）24小时内处理，普通举报3个工作日内处理

### 4.10 作品标签
需要，只能选预设标签（不能自定义）

### 4.11 预设标签（5个）
原创，二创，教程，测评，讨论

### 4.12 内容安全与审核机制

**分级审核制度（参考Civitai）：**
| 级别 | 说明 | 适用范围 |
|------|------|----------|
| 公开 | 无限制，所有用户可见 | 正常内容 |
| 潜在不当 | 需确认年龄 | 轻微暴露、暴力暗示 |
| 受限 | 18+内容，需登录 | 成人内容（高达本子等） |
| 举报触发 | 收到举报后降级 | 被举报的可疑内容 |

**图片安全检测：**
- 上传时自动检测（计划集成第三方，如腾讯云内容安全）
- 检测维度：色情、暴力、政治敏感、品牌侵权
- 检测结果：安全/疑似/危险
- 危险内容直接拒绝，疑似内容进入人工审核

**文本内容过滤：**
- 评论、作品描述支持敏感词过滤
- 敏感词库可后台配置
- 替换/屏蔽/拒绝三种处理方式

**AI辅助审核（后续实现）：**
- 第一期：纯人工审核
- 第二期：AI预检+人工复核（降低审核压力）

### 4.13 版权保护机制（针对高达模型社区）

**版权声明要求：**
- 作品上传时必须选择版权类型：
  - 原创：自己制作的模型/照片
  - 二创：在官方模型基础上改造
  - 引用：引用他人作品（需授权证明）
- 未声明或声明不实，平台可下架

**机体信息来源标注：**
- 用户关联的机体需标注来源（官方/同人/自制）
- 官方机体信息需附版权方信息
- 避免版权纠纷

**图片/作品水印：**
- 平台对展示图片自动添加水印（右下角小logo）
- 下载原图时可选添加水印（免费用户强制水印）
- 水印内容：用户名 + 时间戳

**侵权举报快速处理：**
- 版权方投诉入口（邮箱：copyright@gundam-site.com）
- 侵权投诉表单：作品链接、版权证明、联系方式
- 受理后24小时内下架，3个工作日内核实处理

**原创保护：**
- 发布时可选开启"原创保护"（需付费）
- 开启后自动记录发布时间戳
- 发生纠纷时可作为创作证明

**高达模型特有规则：**
- 禁止上传含有政治宣传、色情低俗的改机作品
- 官方机体模型图片需标注是否为官方摄影
- Bandai官方版权内容仅供欣赏，禁止商业售卖

### 5.5 创作者生态体系（参考Civitai）

> **关联章节**：用户系统（三）、等级系统（十二）、成就系统（十六）
> - 成长路径与用户等级挂钩
> - 资深创作者的"100赞"由成就系统（十六）统计
> - 正式创作者需申请审批（见三、3.6）

**创作者成长路径：**
| 阶段 | 条件 | 权益 |
|------|------|------|
| 新手 | 注册成为普通用户 | 限发1篇作品（见三、3.7） |
| 正式创作者 | 申请+审批（见三、3.6） | 无限发布、专属主页 |
| 资深创作者 | 累计被赞100次+作品数50个 | 首页推荐资格 |
| 官方认证 | 官方审核 | 官方标识、优先展示 |

**说明**：
- "累计被赞100次"：所有作品收到的点赞总数达到100次（不是单作品100赞）
- "作品数50个"：发布的作品总数达到50个
- 两个条件同时满足才能成为资深创作者

**创作者数据面板：**
- 作品总浏览量
- 作品总点赞数
- 粉丝增长趋势
- 单作品平均表现
- 流量来源分析

**创作者激励体系：**
- 每周精选作品推荐（编辑推荐）
- 月度创作者榜单（首页展示）
- 优质创作者奖励（实物/优惠券）

**创作者服务：**
- 专属客服通道（高级档）
- 优先审核通道（高级档）
- 数据分析报告（高级档）

**创作者社区：**
- 创作者专属话题/标签
- 创作者线下活动
- 创作交流群（Discord/微信）

### 5.6 用户主页展示

## 十、文件存储

### 10.1 存储方案
本地存储（服务器硬盘）
- 文件存在服务器本地
- 数据库只存储文件路径

### 10.2 数据库存什么
文件路径，例如：`/uploads/xxx.jpg`

### 10.3 硬盘存什么
实际文件：图片、视频、3D模型文件

### 10.4 文件大小限制

| 类型 | 限制 | 说明 |
|------|------|------|
| 图片 | 单张20MB | 够用，高清照片也没问题 |
| 视频 | 单个500MB | MMD视频一般200-400MB |
| 3D模型 | 单个100MB | glb格式一般10-50MB |

### 10.5 目录结构

```
/uploads
├── /avatars          # 用户头像
│   └── /{user_id}
│       ├── original.jpg   # 原图
│       └── thumb.jpg     # 缩略图 200x200
├── /creations        # 作品文件
│   └── /{creation_id}
│       ├── /images
│       │   ├── original.jpg
│       │   ├── large.jpg   # 1200px
│       │   ├── medium.jpg  # 600px
│       │   └── thumb.jpg   # 200px

├── /banners          # Banner图
├── /cards            # 卡牌图片
└── /watermarked     # 带水印的临时文件（可定时清理）
```

### 10.6 文件命名规则

**命名格式**：`{type}_{user_id}_{timestamp}_{uuid}.{ext}`

| 字段 | 说明 |
|------|------|
| type | 类型：avatar/creation/banner/card |
| user_id | 用户ID |
| timestamp | 时间戳（秒级） |
| uuid | 随机UUID前8位 |
| ext | 扩展名（统一转webp） |

### 10.7 文件上传API

```
  code: 200,
```

**上传作品图片**

```
  - file: 图片文件（限制20MB）
  - creationId: 作品ID

  code: 200,
  data: {
    url: "/uploads/creations/456/images/original.webp",
    largeUrl: "/uploads/creations/456/images/large.webp",
    mediumUrl: "/uploads/creations/456/images/medium.webp",
    thumbUrl: "/uploads/creations/456/images/thumb.webp"
  }
}
```

### 10.8 图片处理流程

**上传时自动处理（sharp库）**：
1. **格式转换**：统一转为webp（动图保持gif）
2. **压缩**：质量85%，保持清晰
3. **生成缩略图**：
   - thumb: 200x200（正方形裁剪）
   - medium: 600px（保持比例）
   - large: 1200px（保持比例）
4. **添加水印**：右下角，透明度30%
5. **存储**：生成的文件写入对应目录

### 10.9 文件删除处理

**软删除时文件处理**：
- 文件不立即删除，标记`is_deleted=1`
- 定期清理任务（每周）删除7天前未引用的文件
- 引用计数为0时才能被清理

**硬删除时文件处理**：
- 彻底删除时，文件同时从硬盘删除
- 相关缩略图、水印文件一并删除

### 10.10 文件类型校验

| 类型 | 允许格式 | MIME类型 |
|------|----------|----------|
| 图片 | jpg/jpeg/png/webp/gif | image/* |
| 视频 | mp4/webm | video/* |
| 3D模型 | glb/gltf | model/gltf-binary |

**校验方式**：
1. 扩展名白名单校验
2. MIME类型校验
3. 文件头魔数校验（防止伪造）

### 10.11 用户存储配额

| 订阅档位 | 图片总大小 | 视频总大小 | 3D模型数量 |
|----------|------------|------------|------------|
| 免费 | 100MB | 0 | 0 |
| 基础档 | 500MB | 0 | 0 |
| 标准档 | 2GB | 1GB | 3个 |
| 高级档 | 10GB | 5GB | 无限 |

### 10.12 CDN预留

**路径格式（兼容后期迁移）**：
- 当前：`/uploads/creations/xxx.webp`
- 后期迁移CDN后：`https://cdn.gundam-site.com/uploads/creations/xxx.webp`

## 十二、等级/XP系统

> **关联章节**：每日任务（十三）、签到系统（十四）、成就系统（十六）
> - XP来源：每日任务（十三）、签到系统（十四）、成就奖励（十六）
> - XP是升级的唯一条件，攒够XP且满足条件即可升级

### 12.1 等级系统
- 共30级
- 通过XP经验值累积 + 固定条件触发升级

### 12.2 XP来源（汇总）

| 来源 | XP范围 | 说明 |
|------|--------|------|
| 每日任务 | 随机1-5 XP/任务 | 见十三、每日任务系统 |
| 签到 | 5-30 XP/天 | 见十四、签到系统（连续天数越高越多，封顶30XP） |
| 成就奖励 | 10-1000 XP/个 | 见十六、成就系统 |

### 12.3 升级条件规则（重要）
XP够了 + 条件满足，才能升级
- 如果XP够了但条件不满足，XP无法继续获取
- 例如：10级需要2000XP + 发25篇作品
- 如果XP满了2000但作品只有1篇，XP无法继续累积，必须先满足作品条件

**成就奖励特殊处理**：
- 成就奖励XP属于里程碑式额外奖励，即使日常XP已达上限（无法继续获取），成就XP仍然到账
- 原因：成就代表重大里程碑，应该被认可，不受日常XP限制影响
- 但如果用户因条件不满足而无法升级，即使XP超出要求也不会触发升级
- 超出的XP会累积，用于满足条件后的下一级升级

- **说明**：连续天数越高，单日XP越多，鼓励持续签到；封顶避免数值过大

### 14.4 连续签到断了怎么办
从第1天重新开始，但可购买补签卡补签
- 断了后连续天数归零
- 可使用补签卡补回漏签的天数（补签不恢复连续天数，只补发XP和卡牌）

**三套连续计算规则（重要）**：
| 场景 | 计算规则 | 说明 |
|------|----------|------|
| 排行榜连续天数 | 不恢复 | 断了就断了，即使补签也不恢复历史最高 |
| 当日连续奖励 | 从5XP重新计算 | 补签当天按连续1天给5XP（不是按实际断开天数） |
| 成就连续天数 | 补签计入连续 | 补签的日期视为"签到成功"，成就统计按实际签到计算 |

**示例**：连续签到2天后断了，第3天补签
- 排行榜：最高连续天数仍为2（第3天补签不算连续）
- 当日奖励：第3天补签给5XP（按连续1天计算）
- 成就：第3天补签后，成就会显示"连续3天"（补签那天算第3天）

### 14.5 签到数据保留
- 最高连续签到天数（记录历史最高）
- 累计签到总天数
- 显示在个人主页
- 可加入签到排行榜

### 14.6 签到排行榜
按最高连续天数或累计总天数排序

### 14.7 签到历史
可查看签到历史（哪天签到了）

**显示内容**：
- 日期（哪天签了）
- 获得XP（基础5XP+连续奖励）
- 是否补签（显示"补签"标签）

### 14.8 补签卡入口
签到日历页面显示"补签"按钮
- 有漏签日期且有补签卡时，按钮可用
- 点击后弹出日历选择器，只能选择漏签的日期
- 确认后扣除1张卡，补发XP和卡牌

### 14.9 补签卡使用规则
**来源**：
- 订阅用户每月获赠（基础0张、标准1张、高级3张）
- 单独购买：3元/张，5元/3张
- 每月限购6张
- 按注册日期每月重置，不累积（例：15日注册则每月15日清零）

**使用方式**：
- 点击"补签"按钮，选择补签日期（必须是漏签的日期）
- 扣除1张补签卡，补发该天的XP（按连续1天计算：5XP）
- 补签不恢复连续天数，连续天数保持断裂状态

### 14.10 签到与卡牌系统关联
每日签到随机获得一张卡牌（见十五、卡牌系统）
- 签到时随机抽取卡牌
- 抽取概率按卡牌稀有度（普通50%/稀有28%/卓越15%/史诗6%/传说1%）
- 补签也会获得卡牌

## 二十五、支付接入

### 25.1 支付方式
微信支付+支付宝（国内主流）
- 后续可扩展Stripe（支持国际信用卡）

### 25.2 支付流程
1. 用户选择订阅档位
2. 发起支付（跳转支付页面）
3. 支付成功后回调通知
4. 更新用户订阅状态

### 25.3 订阅周期
月付/年付两种
- 月付：按自然月续费
- 年付：按年续费，通常有优惠

### 25.4 自动续费
- 订阅到期前3天发送续费提醒（站内通知+邮件）
- 到期当天自动扣款续费
- 续费失败后最多重试3次（每天1次）
- 重试期间保持当前订阅状态（不降级）
- 重试3次都失败后，第4天发送"续费失败"通知，24小时后降级为免费档
- 降级后用户可以随时重新订阅

### 25.5 取消订阅
- 用户可随时取消（取消后到期前仍可使用）
- 取消后不退款，按剩余时间折算
- 取消操作：用户设置页 → 订阅管理 → 取消订阅
- 取消后不影响当月已享受的服务，到期后按免费档处理

### 25.6 订阅过期处理
**内容访问**：
- 已付费解锁的内容（如作品详情）仍可查看
- 但不能再使用付费功能（如上传新作品）

**数据处理**：
- 超过30天未续费，清除存储配额中的视频和3D模型（图片保留）
- 补签卡按注册日期每月重置，与订阅状态独立

**恢复订阅**：
- 续费后立即恢复所有功能
- 补签卡数量按新档位重新计算

### 25.7 退款政策
- 7天内可申请退款（特殊情况）
- 超过7天不接受退款申请
- 退款流程：联系客服 → 审核 → 原路退回

### 25.8 支付安全
- 使用官方支付API
- 签名验证防止伪造回调
- 订单记录完整可查

### 26.6 Webhook规范

**Webhook用途**：
- 支付回调（微信/支付宝）
- 内容审核结果通知

**Webhook安全**：
```typescript
// 验证签名
function verifyWebhook(token: string, payload: string, signature: string): boolean {
  const expected = crypto
    .createHmac('sha256', token)
    .update(payload)
    .digest('hex');
  return crypto.timingSafeEquals(Buffer.from(signature), Buffer.from(expected));
}
```

**Webhook重试机制**：
- 最多重试3次
- 重试间隔：1分钟、5分钟、30分钟
- 返回success才停止重试

**Webhook日志**：
- 记录请求时间、Payload、响应、签名验证结果

**消息类型**：
| type | action | 说明 |

**连接认证**：
- 连接时携带JWT Token
- 心跳间隔：30秒
- 断线重连：指数退避（1s, 2s, 4s, 8s...）
